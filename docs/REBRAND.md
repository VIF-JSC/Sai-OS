# Brand map and rename guide

This document lists **every place the brand appears** in the repository. To rename the OS
(for example `Sai` → another name), follow the checklist at the end; this file contains all
the information needed to do it completely.

The brand has **two layers** that change independently:

| Layer | Current value | Appears in |
|---|---|---|
| **Display name** | `Sai` | Boot menu, os-release, welcome page, slideshow, logo |
| **Technical slug** | `sai` | File names, hostname, binaries (`sai-update`), the `/usr/share/sai` path |

Also: the ISO file `Sai-<version>-amd64.iso` and the volume label `SAI` (A-Z0-9_ only).

---

## 1. Display-name touchpoints

| File | Contents |

| `os/provision.d/80-debrand-deep.sh` | Replaces the visible "Linux Mint" in mint* apps + live-installer with `$SAI_NAME` |
| `os/provision.d/85-installer-brand.sh` | live-installer logo + welcome.svg + slideshow + `style.css` colors; patches the language preselect to **en_US** (stops geoip from picking Vietnamese) |
| `os/rootfs/usr/share/sai/welcome/index.html` | Title, text logo (S + "ai"), footer |
| `os/rootfs/usr/share/sai/slideshow/index.html` | Slideshow content + brand mark in the corner |
| `os/rootfs/etc/apt/sources.list.d/sai.sources` | Comment |
| `README.md`, `LICENSE-BRAND.md`, `CREDITS.md` | Name in the documentation |
| `.github/workflows/build.yml` | Workflow name, `Sai-*.iso` glob |
| `.gitignore` | `Sai-*.iso` glob |

## 3. Logo and colors — one source

The brand assets are generated by `brand/apply.py` from source files in `brand/tmp/` (not
committed; delivered by the designer). To change the artwork, drop the new files into
`brand/tmp/` under the expected names and run the script again.

Colors used outside `apply.py` (change by hand):
- `os/rootfs/usr/share/glib-2.0/schemas/99_sai.gschema.override` — `primary-color`/`secondary-color` (desktop fallback color)
- `os/rootfs/usr/share/sai/slideshow/index.html` — CSS `--brand`, `--brand-deep`
- `os/rootfs/usr/share/sai/welcome/index.html` — CSS `--brand`, `--brand-deep`
- `os/provision.d/90-boot-splash.sh` — Plymouth background and progress-bar colors (`0x...` hex)
- `builder/iso.sh` — `color_highlight=cyan/black` (GRUB menu highlight)
- `os/provision.d/85-installer-brand.sh` — the live-installer `style.css` heredoc

**File → usage table** (replacing a file with the same name and size requires no code change):

## 4. Do NOT change (technical and legal identifiers)

| Item | Reason |
|---|---|
| `ID_LIKE="debian linuxmint"`, `VERSION_CODENAME=gigi`, `DEBIAN_CODENAME=trixie` (in `10-identity.sh`) | System tools look these up; changing them breaks apt and drivers |
| The `/etc/linuxmint/info` path | mintinstall/mintupdate read this path; its contents already carry the Sai brand |
| Package names `mintinstall`, `mint-artwork`, ... and `mintinstall.desktop` in pinned-apps | Real Mint application IDs |
| `/usr/share/doc/*/copyright` in the ISO | Must be preserved under the GPL — **never sed these** |
| Plain `linuxmint` strings in code (paths, imports, URLs) | Technical, not displayed |

Visible debranding of the mint* apps is done at build time by `80-debrand-deep.sh`, which
replaces only the exact phrase `"Linux Mint"` in UI text files, following `$SAI_NAME`.

## 5. Rename checklist (in order)

Assuming `Sai`/`sai` → `NewName`/`newname`:

1. **File contents** — replace in this order (specific first, generic last):
   - Slug compounds: `saibuild`→`newnamebuild`, `sai-update`→`newname-update`, `sai-logo`, `sai-theme-apply`, `sai-first-run`, `sai-welcome` (+ the `.config/sai-welcome-seen` stamp), `sai-input-setup`, `sai-fcitx5`, `sai-lockup`, `sai-release-stamp`, `sai-dark/light/wallpaper`, `00-sai-desktop`, `99_sai.gschema`, `sai.plymouth`, `sai.sources`, `sai.internal`
   - Paths: `backgrounds/sai`, `share/sai`, `etc/sai`, `themes/sai`, `lib/sai`
   - Boot parameters: `username=sai`, `hostname=sai`
   - Variables: `SAI_` → `NEWNAME_` (env.sh, iso.sh, rootfs.sh, workflow, provisioning)
   - Display: `Sai` → `NewName` (including "Install Sai" and "Start Sai")
   - Remaining standalone words: `\bsai\b` → `newname`
2. **Rename files and directories** containing `sai`/`Sai` (recursive, depth-first). With a
   Python `os.walk`, prune with `dirs[:] = [d for d in dirs if d != ".git"]`; filtering with
   `".git" in path` would skip `.github/`.
3. **Logo**: place the new brand assets in `brand/tmp/` and run `brand/apply.py` (adjust the
   output file names in the script to the new brand).
4. **Verify**: `make test` plus a repo-wide grep for the old brand (excluding `.git`).
5. **ISO volume label** (`ISO_LABEL`): `A-Z 0-9 _` only, no hyphens or spaces.
6. Update this file for the new brand.

## 6. Known remaining Mint traces (accepted or to be handled later)

| Trace | Visibility | Note |
|---|---|---|
| `.mo` translations of mint* apps (with the UI in Vietnamese a few strings still say "Linux Mint") | Low | `.mo` files are binary; fixing them means editing the `.po` sources and recompiling |
| F1 help text in the BIOS boot menu (gfxboot) | Very low | Inside the `isolinux/bootlogo` cpio archive; requires unpacking and repacking |
| Help links in mint* apps pointing to linuxmint.com | Low | Can be sed-replaced with your support page once you have one |
| Icons of `mintinstall`/`mintupdate` | Very low | Generic bag/shield icons, no Mint text |
| Comment in `/etc/apt/sources.list.d/official-package-repositories.list` | Not displayed | Technical, kept |

## 7. Placeholder values to replace for a real deployment

The repository ships **placeholder** values so anyone can build. For your own deployment, replace:

| Placeholder | Where | Replace with |
|---|---|---|
| `https://sai.internal/` | `os/provision.d/10-identity.sh` (HOME_URL, SUPPORT_URL, BUG_REPORT_URL, the `*_URL` keys in `/etc/linuxmint/info`), `os/rootfs/etc/firefox/policies/policies.json` (Homepage, ManagedBookmarks) | Your home page, intranet or project site |
| `https://ota.sai.internal/apt`, `Enabled: no` | `os/rootfs/etc/apt/sources.list.d/sai.sources` | Your APT repository (aptly/reprepro); put the public key at `usr/share/keyrings/sai-archive-keyring.gpg` (the `Signed-By` target, not present yet) and set `Enabled: yes`. Migration workflow: `os/rootfs/usr/share/sai/migrations/README.md` |
| "Contact the IT team" | `os/rootfs/usr/share/sai/welcome/index.html` (footer), `slideshow/index.html` (Maintenance slide) | Support email, extension, ticket link or GitHub Issues |
| Firefox bookmark folder and title in `policies.json` | `os/rootfs/etc/firefox/policies/policies.json` | Your bookmark names |
| Empty templates | `os/rootfs/etc/skel/Templates/` | Your document templates (.docx/.xlsx) |

Quick search: `grep -rn 'sai.internal' . --exclude-dir=.git`.

Unattended installation is not supported: LMDE's live-installer has no ubiquity-style preseed.
The boot menu only offers a direct path into the interactive installer; large-scale deployment
would require `live-installer-expert-mode` or scripting its answer file.
